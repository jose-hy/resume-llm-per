## Setting up the database

This project uses PostgreSQL, hosted on EC2 in the us-east-1 region.

To set up the database:

- Create AWS EC2 instance with Ubuntu and t4g.nano

- Update your system packages:

```
sudo apt update
sudo apt upgrade -y
```

- Install PostgreSQL and its contrib package:

```
sudo apt install postgresql postgresql-contrib -y
```

- Start & Enable PostgreSQL Service:

```
sudo systemctl start postgresql
sudo systemctl enable postgresql
sudo systemctl status postgresql
```

- Change the postgres user password:

```
sudo -u postgres psql
\password postgres
```

- To allow remote connections, modify PostgreSQL configuration:

```
sudo nano /etc/postgresql/*/main/postgresql.conf
```

Change:

```
#listen_addresses = 'localhost'
```

to:

```
listen_addresses = '*'
```

- Save changes
- Edit conf file:

```
sudo nano /etc/postgresql/*/main/pg_hba.conf
```

- Add this to end of file:

```
host    all             all             0.0.0.0/0               md5
```

- Restart postgres:

```
sudo systemctl restart postgresql
```

Update your EC2 security group to allow traffic on port 5432

## SQL table queries

### Create analytics table

```
CREATE TABLE analytics (
    timestamp TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    data JSONB NOT NULL,
    type TEXT NOT NULL,
    username TEXT NOT NULL,
    id BIGINT NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    PRIMARY KEY (id),
    UNIQUE ((data ->> 'session_id'), username, type)
);
```

### Create user table

```
CREATE TABLE "user" (
    id BIGINT NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    password TEXT NOT NULL,
    username TEXT NOT NULL,
    PRIMARY KEY (id),
    UNIQUE (username)
);
```

### Create applied_to table

```
CREATE TABLE applied_to (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    job_id text,
    job_title text,
    url text,
    location text,
    remote boolean,
    created_at timestamptz DEFAULT CURRENT_TIMESTAMP,
    applied_to_count smallint DEFAULT 0,
    UNIQUE (job_id, job_title)
);
```

### Connecting to the database

The database can be accessed via EC2 Instance Connect and running
```
sudo -u postgres psql
\c resume_matching
```

or by running in your local command line with:

```
psql -h 52.6.81.11 -p 5432 -U postgres -d resume_matching
```

You will also be prompted to enter the database password

## Setting up the server

The server handles analytics and authentication. It's built with Java Spring Boot and is hosted on EC2.

### Running locally

- Install Java (SDK 24.0.1) and Maven 

- Start the local server

```
env=development mvn spring-boot:run -Dspring-boot.run.jvmArguments="-DDB_URL='jdbc:postgresql://<EC2_IP_ADDRESS>:5432/resume_matching' -DDB_PASSWORD='<PASSWORD>' -DSECRET_KEY='<SECRET_KEY>' -Denv=development"
```

Note: it's recommended to connect to a locally running database

### Building Docker image and uploading to Elastic Container Registry

- Log in to AWS via the command line on your local terminal

- Authenticate Docker client with registry:

```
aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin 593510232307.dkr.ecr.us-east-1.amazonaws.com
```

- Build image

```
docker build -t resume-matching .
```

- Tag the image:

```
docker tag resume-matching:latest 593510232307.dkr.ecr.us-east-1.amazonaws.com/resume-matching:latest
```

- Push to the registry:

```
docker push 593510232307.dkr.ecr.us-east-1.amazonaws.com/resume-matching:latest
```

To set up, create an EC2 instance with Amazon Linux and t4g.nano

- Install docker:

```
sudo yum install docker -y
```

```
sudo service docker start
```

```
sudo systemctl enable docker
```

- Check for any running processes

```
docker ps
```

- Stop running instances

```
docker stop <container_id>
```

- Authenticate with AWS

```
aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin 593510232307.dkr.ecr.us-east-1.amazonaws.com
```

- Pull most recent image

```
docker pull 593510232307.dkr.ecr.us-east-1.amazonaws.com/resume-matching:latest
```

- Start server:

```
sudo docker run -d -p 8080:8080 -e SECRET_KEY=<secret_key> -e DB_URL=jdbc:postgresql://<EC2_IP_ADDRESS>:5432/resume_matching -e DB_USERNAME=postgres -e DB_PASSWORD=<PASSWORD> -e SPRING_PROFILES_ACTIVE=prod -e env=production 593510232307.dkr.ecr.us-east-1.amazonaws.com/resume-matching
```

### SSL and certificate renewal

The server uses nginx for port forwarding from port 443 to port 8080.

For the SSL cert, Let's Encrypt is used. This cert only lasts 90 days but is renewed every 12 hours using a cron job

This cron job (using crontab) runs twice a day and stops the nginx port forwarding:

```
0 0,12 * * * sudo systemctl stop nginx && sudo certbot renew && sudo systemctl stop httpd && sudo systemctl start nginx 
```

## Setting up analytics dashboard

The dashboard is built with Grafana. It uses the following SQL queries:

### Number of jobs clicked on vs number of jobs fetched (bar chart)

```
select
  (data ->> 'viewed') :: int as viewed,
  (data ->> 'clicked_on') :: int as clicked_on,
  ROW_NUMBER() over () :: text
from
  analytics
where
  type = 'jobs_viewed'
limit
  30;
```

### Daily active users (bar chart)

```
select
  date_trunc('day', "timestamp") as day,
  SUM((data ->> 'count') :: int) as count
from
  analytics
GROUP BY
  date_trunc('day', "timestamp")
order by
  date_trunc('day', "timestamp") asc
limit
  15;
```

### Top ten jobs (bar chart)

```
select
  url,
  count,
  CASE WHEN length(job_title) > 30
  THEN (left(job_title, 30) || '...') 
  ELSE job_title
  END job_title,
  location,
  remote,
  created_at
from
  applied_to
where
  created_at >= NOW() - interval '3 days'
order by
  count desc
limit
  10;
```

## How authentication and authorization works

- The Spring Security library is used to facilitate auth
- When a user submits their email and password, their password is hashed with bcrypt and stored in the database.
- Spring Security creates a JWT based on the secret key
- JWT is sent back to the client and stored in browser's cookies (these are called HTTP cookies)
- When the client sends a request, it attaches the cookie so that the server can authorize the request
